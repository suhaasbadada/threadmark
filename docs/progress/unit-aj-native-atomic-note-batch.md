## Product and stable acceptance

**AJ-01 — explicit finite occasional management.** Stage copies only the loaded
existing note's Update intent from a view-owned draft plus its captured Edit
base, or Retire intent from loaded latest history. One namespace, distinct IDs,
2–8 actions, 4096 bytes/text, 32768 total copied text and 65536 encoded request.
One entry may be collected but not reviewed/applied. No Add, missing-ID fallback,
autoload, latest substitution, auto-rebase or single-write loop. Staging, removing,
clearing, editing copied intent by restaging, opening/canceling Review do no service
or filesystem I/O. They never rewrite editor/history/base/original. Review freezes
the exact copied entries and histories, plan generation, model generation,
configuration and root/identity/incarnation binding. UI shows count, action, IDs,
expected revisions, kind, text and captured retirement history, plus human-context
not-truth and Retire-not-Forget disclosures. New controls use labeled native
buttons and keyboard Cancel; no GUI/AX walkthrough claimed.

**AJ-02 — no pending-review transport bypass.** Public Operation requires opaque
`BatchExecution`, not public `BatchReview`. Internal constructor/claim/revoke,
lock-protected one-use state. Only the owned model task mints after all predecessor
joins, refresh-driver shutdown, fresh namespace check and current review fences.
Synchronous cancellation invalidation and task cancellation handler revoke now;
completion/error defer revokes again. ProcessService claims exactly once and
decodes against the captured internal plan without reclaiming. Ordinary import
cannot construct execution, dispatch pending review or set publications/access
registry/controllers. This is an API guardrail, not authentication against
malicious in-module code. Old trusted public single-note writers are unchanged.

**AJ-03 — byte-exact bounded transport.** Typed closed AI argv contains no note
text; validated JSON stdin only. Complete metadata receipt <=8192 including LF;
closed top/action keys, decoded duplicate rejection, integer tokens/types, exact
version/project/count, ID-sorted complete actions and exact old/new revisions and
operation. No partial prefix or response-selected targets. Retained original frame
is independently revalidated against captured plan at model adoption. No request
text, root or OS path in new diagnostics/status. Text appears only in explicit
local management review/editor. Actual 8 x 4096-byte request traverses the process
fixture; inherited single-note input limits remain 4096.

**AJ-04 — lifetime, CAS and preservation.** Model registry cancels/joins every
predecessor before successor service/spawn/write, including cancellation-ignoring
fake. Generation/configuration/project/note/history/plan/editor/review changes
revoke late publication; stage removal and Cancel/Quit revoke execution. Staged
intent remains in memory across invalidation unless explicitly removed/cleared;
another namespace cannot stage into it. Nothing automatically rebases history or
the view-owned Edit binding. Batch success leaves loaded history/editor/base/
original and an existing CAS conflict intact. Only explicit reload/Edit follows
the existing T/V rebase policy. Source policy/snapshot is independent of this
human namespace capture; batch grants no source authority/provider/host access.

**AJ-05 — uncertainty and receipt versus refresh.** Once mutation dispatch begins,
CLI/decode/cancel/post-write namespace-corroboration failure is unknown persisted
outcome, never rollback/no-effect. Retain intent, no automatic retry or fallback;
each target must explicitly reload history and restage from a fresh Edit base
before a new review. Pre-dispatch queued cancellation never claims or writes.
Unknown outcome also has a persistent, separate UI warning: staging/editing or
explicitly clearing intent cannot hide it or imply rollback. A delayed restage
during Apply cancellation is covered by the lifecycle fixture.
Whole complete acknowledgment plus current namespace corroboration establishes
saved batch, then may clear applied intent. Subsequent fresh bound LIST is only
refresh: failure/cancel says saved-but-refresh-failed, never write-failed/no-effect.
No B metadata adoption; no later history refresh replaces editor/base. Native
pre/post metadata checks are not authentication or a revocation lease: core's AI
transaction checks the captured binding before human SQL and provides atomic CAS.

**AJ-06 — actual evidence and honest gates.** Real CLI mixes Update/Retire for
every count 2..8, Cancel Review leaves DB bytes unchanged, explicit Apply saves,
reopen verifies all revisions; source bytes, source evidence, original, history
and old edit base preserved. Any newer peer revision or Forget target rejects
whole batch with n0 unchanged. Genuine real commit then lost receipt/cancel/
same-root nonce replacement exercises unknown state and retained intent, no
fallback writes; completed receipt followed by bound LIST failure remains saved.
Fake exercises delayed preclaim revoke/replay, explicit successor joining,
queued predispatch cancellation, configuration/selection/Quit/editor/review/remove
fences and explicit fresh-history/restage gate. Strict metadata tests cover wrong
target/revision/operation/count/types, escaped duplicates, extra/partial frames,
missing LF, exact 8192 and overflow. AI's inherited Rust/CLI fixtures separately
cover root/nonce/Unicode-before-SQL, dropped metadata and legacy admission; this
unit does not claim a second native SQL instrumentation proof.
