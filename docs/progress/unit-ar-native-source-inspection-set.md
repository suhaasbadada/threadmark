## Product boundary and inherited wire limitation

Only adopted Projects/Query rows mint opaque read-specific handles. Coordinates
alone, Context preview text and human-note rows cannot stage. The immutable request
keeps raw query/mode/AL subset in memory, full captured Project and exact genuine
rows; AQ stdin contains only version/path/line/hash. Canonical order uses FULL
registered-policy positions then line. One owned read calls AQ once, without a
project-show diagnostic, reduced Project, latest substitution or per-anchor loop.
Every approved source still participates in backend freshness/containment.

The separate closed parser retains the complete frame; adoption reparses and
compares the exact typed projection. This is read validation, not new execution
authority or authentication against malicious code in the module. The old single
Inspect route and its parser are unchanged.

AQ v1, like AB/Z v1, has no total-line-count/EOF attestation. Native proves the exact
left edge, consecutive coordinates, one byte-exact center, maximum radius/line
count and right bound. A shorter right edge is accepted as the backend's natural
EOF claim; native cannot independently distinguish a well-formed false early EOF
from a genuine edge without a separately reviewed wire change or extra source I/O.
Neither is introduced. Backend AQ constructs full natural windows; malformed,
partial JSON, missing-center and hole/duplicate windows are rejected. No claim of
independent EOF attestation, filesystem lease, AST/comprehension, reduced source I/O
or measured performance improvement. GUI/AX and future filesystem freshness are
separate, unverified gates.
